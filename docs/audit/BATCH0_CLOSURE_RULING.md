### 2.7 ⚠️ 一条**本批新建的机械判据**：**尺寸不是同一性判据，sha256 才是**
队长在核实缺陷 2 时**意外发现自己的产物与 t33 的同为 `6,030,092 B` 但 sha256 不同**（`B0333B2A…` vs `1401516B…`）——两者编译选项不同（是否含 `-lwinpthread`、`-static*` 等）。
**这直接推翻了一条在本批被实际使用的经验**：`t29` 当年正是**靠"字节数相同"发现误用陈旧 `.o`**。该经验在"同尺寸不同内容"的情况下会**失效**。
> **判据（本批新增）**：**二进制同一性只能用 `sha256` 判定，尺寸与字节数只能作为"不相同"的排除性证据（尺寸不同 ⟹ 必定不同），不能作为"相同"的充分证据。**
该判据归入方法学条目 **M-6（二进制断言须固定 sha256）** 的强化说明，并作为批次 1 交接项（与 M-6 合并，不新增编号）。

## 3. 由本次追加修订暴露出的第 6 条制度缺陷（附可用修法）

### 缺陷：**终态任务不可变** ⟹ 任何"提交后仍需修正"的交付物都必然产生"报告版本 ≠ 任务记录"的错位
本批已出现**三次**同一形态：

| # | 事件 | 具体表现 |
|---|---|---|
| 1 | `t26`（verification）| 队长要求补 `changedPaths` → `Error: terminal task t26 is immutable; use agent_teams_reassign_task to retry failed/cancelled work` |
| 2 | `t33`（verification）| mechanical-fixes-engineer 补跑契约 `verify` 成功（并发冲突排除后 `11/11`），但 t33 已终态，**该次原始输出无法写入其 `commandsRun`** → 记录层缺口 |
| 3 | **`t28`（integration）** | 按队长补充要求形成的 `rev.2` **不在门禁记录内**，需由本裁定文件显式授权与背书 |

**共同形态**：协作中"提交后仍有合法修正"是常态（补充要求、遗漏项、并发发现的缺口），但 **`TASK_TRANSITIONS` 把 `completed` 设为无出边**（`lib/state.js:114-119`），而 `reassign_task` 只服务 `failed`/`cancelled`。于是修正**只能落在任务之外**（报告内部标注、或像本文件这样的旁路裁定），门禁记录与最终交付物之间**必然产生缝隙**。

**可用修法（供后续批次参考）**：
1. 任务文本中**预先声明修订规则**（例如"本任务的交付物允许 rev.N 版本，修订须在报告内留痕并附源码指纹不变性证据"），把"修订"从异常路径变成受控路径；
2. 或对"以文档为交付物"的任务（integration / requirements）允许 `completed → completed(rev.N)` 的自环，并强制附带**源码指纹不变性证据**；
3. 无论哪种，**修订都必须附"业务源码未变"的可复核证据**（本批采用七个锚点指纹 + `ahead/behind = 0 0`），否则修订不得免于重跑断言。

### 4.1 缺陷与修复
- **缺陷**：脚本编译输出为**固定单文件** `tests/pbkdf2_test.exe`（原 `:38`/`:63`）。当另一进程正在执行该文件、而本进程同时重新链接它时，`ld` 报 `cannot open output file tests/pbkdf2_test.exe: Permission denied` → 脚本按设计输出 `RESULT: COMPILE FAILED` 并 `exit 2` —— **一个会被任何人误读为"代码坏了"的假失败**。
- **修复**（仅 `tests/run_tests.ps1`，111 → 126 行）：输出改为 **`tests/pbkdf2_test_$PID.exe`**（每进程唯一，用完即删）；**退出码语义（0/1/2/3）与"不静默跳过"行为零改动**。
