# 校园文明能量站系统设计文档

## 1. 系统概述

校园文明能量站是一个基于 Web 的校园管理系统，旨在通过积分激励机制促进学生文明行为，实现学生行为管理、积分管理、评价管理等功能。系统支持多角色登录，包括学生、教师和管理员，各角色拥有不同的权限和功能。

### 1.1 系统目标
- 建立完善的学生行为评价体系
- 实现学生积分的管理和兑换
- 提供教师对学生的评价和管理功能
- 为管理员提供系统配置和用户管理功能
- 确保系统安全、稳定、高效运行

## 2. 系统架构

### 2.1 技术栈

| 分类 | 技术 | 版本 | 说明 |
|------|------|------|------|
| 后端 | C++11 | - | 服务器端开发语言 |
| 后端 | httplib.h | - | HTTP 服务器库 |
| 后端 | nlohmann/json | 3.12.0 | JSON 序列化/反序列化 |
| 前端 | Vue 3 | 3.3.4 | 前端框架 |
| 前端 | Tailwind CSS | - | 响应式 CSS 框架 |
| 前端 | ECharts | 5.4.3 | 数据可视化图表库 |
| 前端 | FontAwesome | 6.4.0 | 图标库 |
| 认证 | 自定义 Token | - | 基于时间戳的认证机制 |
| 数据存储 | 内存存储 | - | 开发环境使用内存存储 |
| 数据存储 | SQL 数据库 | MySQL/PostgreSQL | 生产环境使用 |

### 2.2 系统架构

系统采用前后端分离架构，具体包括：

1. **前端层**：基于 Vue 3 和 Tailwind CSS 构建的响应式 Web 界面，支持 PC、平板和手机等多种设备。

2. **API 层**：基于 C++11 和 httplib.h 实现的 RESTful API 接口，处理前端请求并返回 JSON 数据。

3. **业务逻辑层**：实现核心业务逻辑，包括用户认证、权限控制、数据处理等。

4. **数据层**：存储系统数据，开发环境使用内存存储，生产环境使用 SQL 数据库。

## 4. 功能模块设计

### 4.1 认证与授权模块
- **登录认证**：支持用户名密码登录，生成基于时间戳的认证 token
- **权限控制**：基于角色的权限管理，不同角色拥有不同的操作权限
- **会话管理**：token 有效期管理，支持会话超时处理

### 4.2 学生端模块
- **个人信息**：查看个人基本信息和积分情况
- **积分记录**：查看积分变动历史记录
- **评价查看**：查看教师对自己的评价
- **商城兑换**：使用积分兑换商品

### 4.3 教师端模块
- **工作台**：查看班级学生统计信息
- **学生管理**：添加、编辑、删除学生信息
- **积分管理**：为学生添加或扣除积分，查看积分记录
- **评价系统**：对学生进行多维度评价
- **数据统计**：查看班级积分统计和评价分布

### 4.4 管理员端模块
- **系统概览**：查看系统运行状态和统计数据
- **用户管理**：管理所有用户，包括添加、编辑、删除用户
- **角色管理**：管理系统角色，包括创建、修改、删除角色
- **权限管理**：管理系统权限，为角色分配权限
- **系统配置**：配置系统基础参数、安全设置、备份策略
- **数据统计**：查看系统级别的数据统计和分析

## 5. API 设计

### 5.1 认证 API
- `POST /api/auth/login` - 用户登录
- `POST /api/auth/logout` - 用户登出

### 5.2 学生 API
- `GET /api/student/info` - 获取学生个人信息
- `GET /api/student/points/records` - 获取积分记录
- `GET /api/student/evaluation` - 获取评价信息
- `GET /api/student/mall` - 获取商城商品

### 5.3 教师 API
- `GET /api/teacher/dashboard` - 获取工作台数据
- `GET /api/teacher/students` - 获取学生列表
- `POST /api/teacher/students` - 添加学生
- `DELETE /api/teacher/students` - 删除学生
- `POST /api/teacher/points` - 积分操作
- `GET /api/teacher/points/records` - 获取积分记录
- `GET /api/teacher/evaluation/dimensions` - 获取评价维度
- `POST /api/teacher/evaluation` - 添加评价
- `GET /api/teacher/statistics` - 获取数据统计

### 5.4 管理员 API
- `GET /api/admin/dashboard` - 获取系统概览
- `GET /api/admin/users` - 获取用户列表
- `POST /api/admin/users` - 添加用户
- `DELETE /api/admin/users` - 删除用户
- `GET /api/admin/roles` - 获取角色列表
- `POST /api/admin/roles` - 添加角色
- `GET /api/admin/permissions` - 获取权限列表
- `GET /api/admin/system/config` - 获取系统配置
- `GET /api/admin/statistics` - 获取系统统计

## 6. 安全设计

### 6.1 认证安全
- 使用基于时间戳的 token 认证机制
- token 包含用户 ID 和角色信息
- token 有有效期，超过有效期需要重新登录

### 6.2 权限安全
- 基于角色的权限控制
- 每个 API 端点都有权限检查
- 防止越权访问

### 6.3 数据安全
- 密码加密存储
- 敏感数据传输加密
- 防止 SQL 注入攻击

### 6.4 防暴力破解
- 登录失败次数限制
- 登录尝试间隔限制
- 验证码机制（可选）
